# 0006. The system layer: generated moments and icons, components per card, shots beside boards

- Status: accepted
- Date: 2026-11-12
- Issue: #56

## Context

The approved design (`docs/design/18-approved`) is two layers. Design 1 is the system: tokens,
79 icon masks and the component cards in `system/project/components/`, built on `bundle.css`.
Design 2 is the moments: warm accents for what is won, which **lived beside the system in
`moments.css`**, not in the tokens. The app had neither. It drew 10 Canvas glyphs and a few
workout parts (`Btn`, `Segments` in `workout/Parts.kt`), but no system icons and no system
components. **Nothing put a shot of the app beside its board**, so "matches the design" was a
claim no one could check.

## Options

**Moments, roles and icons.** (a) Generate them, like every colour: `tokens.py` for the
moments and design 1's roles, a new `icons.py` for the icons, CI diffing both. (b) Type them
into Kotlin by hand: no generator, two copies of every value and path that drift.

**Components.** (a) Build them in one package, one file per system card, and let each screen's
own issue adopt them. (b) Build them and rewire the five built screens in this issue: one pull
request that changes every screen at once, and every screen's flows and shots with it.

**Proof.** (a) Shoot each card's gallery in the simulator at the board's size and render the
card at the same scale, so a person sets the two side by side. (b) Pixel-diff tests: the face
differs between the simulator and Chrome, so they fail on every text and prove nothing.
(c) No visual check: the cards stay a claim.

## Decision

**Generated values, components per card adopted by each screen's issue, and shots beside
rendered boards.**

- **The moments and design 1's roles are generated by `tokens.py`** like every colour, into
  `tokens.css`, `tokens.json` and `Tokens.kt` (`StriveMoments`, `StriveRoles`). The contrast
  check covers each moment's text on the nine surface roles a moment can sit on: `SURFACES`
  without `surface-dim` (R2). Design 1's radii, badge corner and next-row tint reach the five
  call sites in `workout/Focus.kt` that hard-coded them (R3).
- **The 79 icons are generated from `bundle.css` by `icons.py`** into `theme/Icons.kt`. It stops
  on what it cannot translate, such as a rect whose corner radius exceeds half its shorter side,
  instead of clamping it. CI reruns both scripts and fails on any diff.
- **Unbounded 700 is bundled** for celebration numbers (`theme/Celebrate.kt`), never fetched.
- **Components live in `se.carlsmeister.strive.ui`, one file per system card:** `Buttons.kt`,
  `Cards.kt`, `Controls.kt`, `Lists.kt` and `Bars.kt` (TitleBars), with `Moments.kt` for
  `moments.css`. Each screen adopts them in its own issue (R7); the built workout keeps its own
  title bar, `Btn` and `Segments`.
- **Every text a component draws keeps CSS's line box** (`CssLineBox` in `theme/Theme.kt`,
  Material 3's own default). The generated type scale stays trimmed, so built screens do not
  move (R7).
- **`.btnrow` is `ButtonRow`, sized as CSS flex sizes it** (`flexWidths`): padding as the
  basis, a weighted share of the free space, a min-content floor. Not equal weights.
- **Press feedback is one modifier, `Modifier.pressable`,** as the Buttons README says: scale
  .96 and dim, pressed in 100 ms, released on the 350 ms overshooting release curve, no scale
  under Reduce Motion. Buttons,
  the ⋯ pill, chips and the bars' pressables use it.
- **`.navtext` is built from the TitleBars README** (`NavText`), though the card draws none.
- **Touch areas stay 44 dp without changing the drawing:** the standalone switch draws 52 × 32
  and the workout bar's Finish a 40 dp capsule; both take taps across at least 44 dp.
- **The fixture is Carl's sample data on one fixed clock** (R10): a process-wide `wallClock` in
  `workout/Logic.kt` that `now()` reads, so pinning it moves every reading and adds no ticker.
  Every test that loads it resets it after.
- **Board shots are 390 × 844 pt at density 3** (1170 × 2532 px, `boardShots` in the iOS
  tests), and `compare.py` renders the board or card beside them at Chrome's device scale 3
  (R9), so a pair has one size and nothing is resized. A card whose content is exactly
  phone-wide renders at 390 with no side padding, as the shot draws it.

Generated, so the app cannot drift from the generators: CI reruns `tokens.py` and `icons.py`
and fails on any diff, and `icons.py` reads `bundle.css` itself, so the icons follow the design
files. **Two things are hand copies that CI does not check:** `MOMENTS` in `tokens.py` copies
`moments.css`, and `Motion.win` and `Motion.calm` in `Theme.kt` copy its spring values. A change
to `moments.css` leaves CI green and the app on the old value. Per
card and adopted later, because rewiring five screens is five issues' worth of flows and
shots. Side by side, because a person reading two pictures catches what a pixel diff drowns in
font noise.

## Consequences

- **Easier:** a design change to a moment, a role or an icon is an edit to `tokens.py` or
  `bundle.css` and a script rerun. Every later issue shoots its boards with `boardShots` and
  pairs them with `compare.py`.
- **Harder:** until the screens adopt them, the built workout draws its own bar, buttons and
  segments, so two looks for the same part coexist. No screen uses the components, the icons
  or the moments yet.
- **Not built:** segmented controls (`.segc`, `.seg`) are #57's (R4). The 10 Canvas glyphs in
  `workout/Parts.kt` stay until a screen swaps them for icons.
- **Two questions go to Carl as issue drafts.** First, the type scale's trimmed line box:
  system components keep CSS's line box while built screens keep the trimmed one, and the whole
  theme should pick one. Second, `bundle.css`'s `.center`: the dialog class also matches
  `.row.center`, so the approved Lists card renders "Add gear" as a full-page overlay.
- **Revisit when** a screen's issue adopts the components: delete its private part, and
  re-shoot that screen beside its board.
